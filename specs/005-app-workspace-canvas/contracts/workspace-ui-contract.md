# UI Contract: 应用工作空间与编排画布

## 入口规则

- 已登录用户打开前端应用时，默认展示个人工作空间页面。
- 未登录用户继续展示认证入口，不得展示工作空间或应用数据。
- 前端不得要求用户手动创建工作空间；首次登录无工作空间时由后端自动创建并返回。

## 工作空间页面

- 页面显示当前默认工作空间名称。
- 页面显示应用卡片列表。
- 当应用列表为空时，显示空状态和创建应用入口。
- 每张应用卡片至少显示：
  - 应用名称
  - 应用说明或状态摘要
  - 最近更新时间
  - 进入应用详情的交互入口
- 页面提供创建应用入口。
- 首版页面不得提供删除应用入口。

## 创建应用

- 创建表单字段：
  - 应用名称，必填，1-80 个字符
  - 应用说明，选填，0-500 个字符
- 提交成功后：
  - 新应用卡片出现在当前工作空间列表中。
  - 用户可继续停留在工作空间列表，也可进入新应用详情；具体导航由实现保持一致即可。
- 提交失败时：
  - 名称为空或超长时显示字段级错误。
  - 同一工作空间名称重复时显示“应用名称已存在”含义的错误。
  - 未登录或会话失效时回到认证入口或显示明确登录失效提示。

## 应用详情页面

- 从应用卡片进入详情后，页面采用左右分栏：
  - 左侧：应用相关信息。
  - 右侧：应用编排画布区域。
- 左侧至少展示：
  - 应用名称
  - 应用说明
  - 应用状态
  - 最近更新时间
- 左侧提供编辑应用名称和说明的入口。
- 保存编辑后，工作空间卡片和详情页展示一致的最新名称与说明。
- 首版不得提供删除应用入口。

## 编排画布首版状态

- 右侧画布区域始终展示空画布状态和“开始编排”入口。
- 首版不得展示或启用以下能力：
  - 新增节点
  - 移动节点
  - 连接节点
  - 删除节点
  - 保存流程
  - 运行或调试流程
- 空画布状态应让用户明确这是后续流程编排入口，而不是加载失败。

## 可访问性与响应式约束

- 所有表单输入必须有可识别标签。
- 按钮的禁用、加载、成功和失败状态必须可见。
- 错误信息必须靠近相关表单或操作区域。
- 卡片和按钮文本在桌面与移动视口下不得溢出或互相遮挡。
- 左右分栏在窄屏下可纵向排列，但应用信息必须先于画布区域出现。

## 前端验证信号

- 浏览器控制台无运行时错误。
- 创建应用后无需刷新即可看到新卡片。
- 编辑名称或说明后，卡片和详情页显示一致。
- 尝试创建或编辑为重复名称时，用户看到明确错误提示。
- 首版界面中找不到删除应用和节点编辑入口。
