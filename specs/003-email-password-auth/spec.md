# Feature Specification: 邮箱验证码与密码认证

**Feature Branch**: `003-email-password-auth`

**Created**: 2026-05-19

**Status**: Draft

**Input**: User description: "实现邮箱验证码和密码登录注册功能，注意需要限制验证码发送频率。登录后，浏览器应自动带上登录凭证，后续请求无需重新登录。过期后应支持刷新。退出登录后应彻底失效。"

## Clarifications

### Session 2026-05-19

- Q: 退出登录后，失效范围应覆盖到哪个会话边界？ → A: 仅当前浏览器当前会话失效，其他设备或浏览器保持登录。
- Q: 验证码发送频率限制应采用哪种粒度？ → A: 同时限制同一邮箱的最小发送间隔和滚动时间窗内的最大发送次数。
- Q: 注册成功后是否应立即建立登录状态？ → A: 注册成功后自动建立登录状态。
- Q: 刷新登录状态时，刷新资格是否应一次性轮换？ → A: 刷新成功后轮换刷新资格，旧资格立即失效。
- Q: 密码强度规则的最低要求是什么？ → A: 至少 8 位，且必须包含字母和数字。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通过邮箱注册账号 (Priority: P1)

访客通过邮箱接收验证码完成邮箱归属校验，设置密码并创建可登录账号。

**Why this priority**: 没有稳定的注册路径，后续登录与会话保持能力都无法成立。

**Independent Test**: 仅实现该故事时，访客应能从输入邮箱开始，完成验证码校验、设置密码并成功进入已登录状态。

**Acceptance Scenarios**:

1. **Given** 访客尚未注册且输入有效邮箱地址，**When** 其请求发送验证码，**Then** 系统向该邮箱发送一次有效验证码，并提示发送结果与再次发送等待时间。
2. **Given** 访客已收到仍在有效期内的验证码，**When** 其提交正确验证码并设置符合规则的密码，**Then** 系统创建新账号、标记邮箱已验证，并自动建立可继续使用的登录状态。
3. **Given** 同一邮箱在最小发送间隔内重复请求验证码，或在滚动时间窗内达到最大发送次数，**When** 访客再次发起发送，**Then** 系统拒绝发送并明确告知仍需等待的时间或剩余可发送条件。

---

### User Story 2 - 使用邮箱和密码登录 (Priority: P1)

已注册用户使用邮箱和密码登录后，浏览器后续访问受保护能力时无需重复输入凭证。

**Why this priority**: 这是用户真正进入系统并持续使用核心能力的基础路径。

**Independent Test**: 仅实现该故事时，已注册用户应能完成登录，并在刷新页面或继续访问时保持已登录状态。

**Acceptance Scenarios**:

1. **Given** 用户邮箱已完成验证且密码正确，**When** 用户提交登录请求，**Then** 系统建立登录状态，浏览器后续请求自动携带所需凭证。
2. **Given** 用户已处于有效登录状态，**When** 用户访问需要身份识别的后续页面或接口，**Then** 系统直接识别用户身份而无需再次登录。
3. **Given** 用户输入错误密码或不存在的邮箱，**When** 用户提交登录请求，**Then** 系统拒绝登录并返回明确、可理解的失败提示。

---

### User Story 3 - 维持、刷新与退出登录状态 (Priority: P2)

已登录用户的登录状态在过期后可被安全刷新；用户主动退出后，既有登录状态必须立即失效。

**Why this priority**: 登录成功后若不能稳定续期或安全退出，会直接影响连续使用体验与账号安全。

**Independent Test**: 仅实现该故事时，测试者应能验证会话临近或达到过期时可刷新恢复，且退出后旧凭证无法再访问受保护能力。

**Acceptance Scenarios**:

1. **Given** 用户存在可续期的登录状态，**When** 原有登录状态到期或即将到期，**Then** 系统允许在有效续期条件下刷新为新的可用登录状态，用户无需重新输入邮箱和密码。
   刷新成功后，上一份刷新资格立即失效并被新的刷新资格替换。
2. **Given** 用户已主动退出当前浏览器会话的登录状态，**When** 当前浏览器继续携带旧登录凭证访问受保护能力，**Then** 系统必须拒绝访问并要求重新登录。
3. **Given** 用户的登录状态与续期资格都已失效，**When** 浏览器发起后续请求，**Then** 系统不得继续识别为已登录用户。

### Edge Cases

- 同一邮箱短时间内高频点击“发送验证码”时，系统应同时按最小发送间隔与滚动时间窗内最大发送次数持续拒绝超频请求，且不得因频繁点击产生多份同时有效的验证码。
- 邮箱已注册但未完成验证时，系统应阻止重复创建账号，并指引用户完成既有注册流程。
- 验证码过期、输入错误、重复使用或被新验证码覆盖后，系统应拒绝其继续用于注册。
- 用户在多个浏览器或设备中保持登录时，某一端退出后，系统应仅使该浏览器当前会话立即失效，其他仍然有效的登录状态保持不变。
- 用户在刷新登录状态时若提交的续期凭证已失效、已撤销、不匹配或已经被新刷新资格替换，系统应拒绝刷新并要求重新登录。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许访客使用邮箱、验证码和密码完成新账号注册，并在注册成功后自动建立登录状态。
- **FR-002**: 系统 MUST 在注册完成前校验邮箱归属，且仅允许通过有效验证码的邮箱完成注册。
- **FR-003**: 系统 MUST 对验证码发送频率施加双重限制，同时覆盖同一邮箱的最小发送间隔和滚动时间窗内的最大发送次数，并在被限制时返回剩余等待时间或等价提示。
- **FR-004**: 系统 MUST 确保同一邮箱在任一时刻仅存在一份当前可用的注册验证码；新验证码生效后，旧验证码必须失效。
- **FR-005**: 系统 MUST 为验证码定义明确的有效期，并在过期、错误、重复使用或被替换时拒绝验证通过。
- **FR-005A**: 系统 MUST 要求注册和登录使用的密码至少为 8 位，且同时包含字母和数字。
- **FR-006**: 系统 MUST 允许已注册且邮箱已验证的用户使用邮箱和密码登录。
- **FR-007**: 系统 MUST 在登录成功后建立浏览器可自动携带的登录凭证，使用户在后续受保护请求中无需重复登录。
- **FR-008**: 系统 MUST 在登录状态过期后提供刷新能力，使仍符合续期条件的用户可在不重新输入邮箱和密码的情况下恢复有效登录状态。
- **FR-009**: 系统 MUST 为登录状态和刷新资格分别定义失效规则，并在任一失效条件满足时拒绝继续使用对应凭证；每次刷新成功后必须签发新的刷新资格并立即撤销旧刷新资格。
- **FR-010**: 系统 MUST 提供退出登录能力，并在退出后立即使当前浏览器当前会话对应的现有登录凭证与刷新资格失效。
- **FR-011**: 系统 MUST 在用户携带已失效、已撤销或不合法的登录凭证访问受保护能力时，返回明确的未登录或需重新登录结果。
- **FR-012**: 系统 MUST 防止未验证邮箱绕过验证码校验直接创建或使用密码登录账号。
- **FR-013**: 系统 MUST 对登录、验证码校验、刷新和退出等关键认证结果提供明确反馈，避免把失败误报为成功。
- **FR-014**: 系统 MUST 保留认证相关操作的可审计记录，以支持排查验证码滥发、异常登录和会话失效问题。

### Key Entities *(include if feature involves data)*

- **用户账号**: 表示可登录主体，包含邮箱、邮箱验证状态、密码凭证状态、账号创建时间与最近认证状态等信息。
- **邮箱验证码**: 表示一次用于验证邮箱归属的短期校验凭据，包含目标邮箱、验证码状态、生效时间、失效时间、发送次数与最近发送时间。
- **登录状态**: 表示浏览器当前可用的登录凭证状态，包含所属用户、签发时间、失效时间、撤销状态与最近使用时间。
- **刷新资格**: 表示可用于续期登录状态的凭证资格，包含所属用户、签发时间、失效时间、撤销状态与替换关系。
- **认证审计记录**: 表示验证码发送、注册、登录、刷新、退出等关键行为的结果记录，包含行为类型、目标主体、发生时间与结果。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 90% 以上首次注册用户可在 3 分钟内完成“发送验证码、验证邮箱、设置密码、进入已登录状态”的完整流程。
- **SC-002**: 95% 以上的成功登录用户在登录后的后续受保护请求中无需再次输入邮箱和密码即可继续使用系统。
- **SC-003**: 100% 的超频验证码发送请求都会被拒绝，并向用户返回可理解的等待提示。
- **SC-004**: 100% 的已退出登录会话在退出后再次访问受保护能力时都会被识别为无效并要求重新登录。
- **SC-005**: 95% 以上符合续期条件的过期登录状态可在 10 秒内完成刷新并恢复可用访问。

## Assumptions

- 本期范围仅包含邮箱注册、邮箱密码登录、登录续期和退出登录，不包含第三方登录、短信登录、找回密码或管理员代登录。
- 注册流程默认要求邮箱先完成验证码校验后才允许账号创建，登录流程默认仅面向已验证邮箱账号开放。
- 注册成功后默认立即进入已登录状态，不要求用户再次手动执行一次登录流程。
- 密码规则已明确为至少 8 位，且必须同时包含字母和数字。
- 浏览器端会自动保存并附带系统签发的登录凭证，用户刷新页面或继续访问时不需要手工再次录入凭证。
- 刷新资格默认采用一次性轮换策略，每次成功刷新后旧刷新资格立即失效。
- 验证码发送限制已明确为针对单个邮箱同时执行最小发送间隔和滚动时间窗内次数上限；如后续需要叠加设备、IP 或全局风控，可在后续规格中扩展。
- 退出登录范围已明确限定为当前浏览器当前会话立即失效，不联动清理该账号在其他终端的已登录状态。
