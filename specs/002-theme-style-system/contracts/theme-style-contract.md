# Theme Style Contract

## 目标

定义项目主题系统对前端开发者的可消费接口，确保主题 token、基础组件样式和验收展示遵循统一约束。

## 1. 主题 Token 契约

### 1.1 必备分类

主题系统必须提供以下语义分类：

- 文本：主文本、次级文本、弱提示文本、反白文本、强调文本
- 背景：页面背景、面板背景、浮层背景、悬停背景、选中背景、禁用背景
- 边框：基础边框、弱边框、强调边框、聚焦边框
- 强调色：主强调、辅助强调、正向状态、警示状态、错误状态
- 视觉节奏：圆角、阴影、间距、字号层级

### 1.2 命名约束

- 必须使用语义命名，不得使用 `red-500`、`page-a-bg`、`card2-shadow` 这类与用途脱节或与页面耦合的命名。
- 新增 token 必须归属已知分类；若确需新分类，必须在主题说明中补充分类用途。
- 基础组件不得直接依赖匿名硬编码值作为主样式来源。

## 2. 基础组件契约

### 2.1 首批覆盖组件

首批基础样式必须覆盖：

- 按钮
- 输入框
- 卡片
- 标签
- 导航项
- 筛选项
- 空态容器

### 2.2 状态矩阵

每个支持交互的组件必须至少定义以下状态中的适用项：

| State | Required Outcome |
|-------|------------------|
| `default` | 组件基础视觉与文本层级清晰 |
| `hover` | 用户可感知悬停反馈，不造成误选 |
| `focus` | 键盘导航时可感知焦点位置 |
| `active` | 按压/触发反馈与悬停态可区分 |
| `selected` | 已选中项具有稳定持续的区分性 |
| `disabled` | 明确不可交互，且不与选中态混淆 |

## 3. 页面层级契约

主题系统必须支持以下页面骨架同时存在且风格一致：

- 顶部导航区域
- 筛选栏/工具栏
- 卡片网格或信息列表
- 空态说明区域
- 可点击面板或浮层容器

要求：

- 页面底层、内容承载层、浮动交互层必须有可感知层级。
- 同一页面内不得出现互相冲突的圆角、边框强度或阴影语言。

## 4. 展示与验收契约

### 4.1 主题展示内容

验收展示必须至少包含：

- token 分类展示
- 基础组件默认态展示
- 基础组件交互态展示
- 至少一个典型工作台式布局片段

### 4.2 人工验收标准

验收时需要能回答以下问题：

- 开发者能否快速定位所需主题语义？
- 基础组件是否都来自统一视觉基线？
- 悬停、聚焦、选中、禁用状态是否可区分？
- 页面层级是否接近用户期望的 AI-Flow 风格方向，而非杂糅旧样式？

## 5. 兼容性约束

- 主题实现必须兼容现有 React + Tailwind CSS 工程结构。
- 在用户已批准的前提下，可以引入 shadcn/ui 及其最小必要依赖，但不得额外扩展未批准的 UI 框架或样式方案。
- 即使使用 shadcn/ui，项目主题 token 仍必须作为颜色、圆角、阴影、边框和状态语义的唯一事实来源。
- 现有页面接入主题时，应优先通过共享样式和共享组件演进，而不是整页重写。
