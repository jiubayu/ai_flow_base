# 快速开始：项目主题样式系统

## 目标

在本地启动前端工程，完成主题系统的实现验证，并通过主题展示页和现有页面检查主题 token、基础组件样式与交互状态是否生效。

## 前置条件

- 已安装 Node.js 20+ 与 `pnpm`
- 当前分支为 `002-theme-style-system`
- 已在 `ui/` 目录安装前端依赖

## 1. 安装依赖

```bash
cd ui
pnpm install
```

说明：

- 本次规划允许按需引入 shadcn/ui 及其最小必要依赖；若实现阶段需要超出该范围的新增依赖，仍必须先取得用户批准。

## 2. 启动前端开发服务

```bash
cd ui
pnpm run dev
```

预期结果：

- Vite 本地服务成功启动
- 浏览器可访问本地前端页面
- 控制台无主题样式加载失败错误

## 3. 验证主题 Token

在主题展示页或展示区中检查：

- 是否存在清晰的文本、背景、边框、强调色、阴影、圆角、间距、字号层级展示
- 是否能从展示中看出页面层级与 AI-Flow 风格方向
- 是否已替换掉原有零散硬编码主色和容器风格

## 4. 验证基础组件样式

检查以下组件是否都有统一样式：

- 按钮
- 输入框
- 卡片
- 标签
- 导航项
- 筛选项
- 空态容器

每类组件至少确认：

- 默认态
- 悬停态
- 聚焦态（如适用）
- 选中态（如适用）
- 禁用态（如适用）

## 5. 验证真实页面接入

检查至少一个现有页面或现有展示模块：

- 主文本、次级文本和说明文字是否来自统一文本层级
- 卡片容器、列表项和页面背景是否来自统一层级语义
- 现有共享组件是否已接入新主题而非继续使用局部硬编码样式

## 6. 执行基础校验

```bash
cd ui
pnpm run typecheck
pnpm run build
```

预期结果：

- 类型检查通过
- 构建通过
- 构建后页面样式未出现明显缺失

## 7. 浏览器人工验收

- 打开主题展示页与实际接入页面
- 检查浏览器控制台无样式相关报错
- 分别验证桌面宽度与移动端窄屏下的基础布局是否可用
- 对照 `contracts/theme-style-contract.md` 检查 token 分类、状态矩阵和页面层级约束是否满足
