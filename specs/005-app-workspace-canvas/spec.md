# Feature Specification: 应用工作空间与编排画布

**Feature Branch**: `005-app-workspace-canvas`

**Created**: 2026-05-20

**Status**: Draft

**Input**: User description: "用户登录后默认应该进入自己的工作空间。在工作空间中可以创建多个应用，工作空间中以卡片的方式来展示应用。进入应用后左侧是应用相关信息，右侧是一张应用编排画布，用于基于流程进行编排。使用 git worktree 的方式来创建和绑定分支。"

## Clarifications

### Session 2026-05-20

- Q: 当前应用编排画布的首版能力边界是什么？ → A: 只展示空画布和入口，不支持编辑流程。
- Q: 同一个工作空间内是否允许创建同名应用？ → A: 不允许，同一工作空间内应用名称必须唯一。
- Q: 用户首次登录但还没有工作空间时，系统应该如何处理？ → A: 自动创建个人默认工作空间并进入。
- Q: 首版工作空间中的应用管理操作范围是什么？ → A: 支持创建应用、查看应用卡片、进入应用详情、编辑应用基础信息，不包含删除应用。
- Q: 首版允许用户编辑哪些应用基础信息？ → A: 应用名称和应用说明。

### Session 2026-05-27

- Q: 知识库文件解析和索引是长时间任务，页面切换或关闭后状态如何保持？ → A: 任务状态必须持久化在后端，知识库详情接口必须返回当前文档最近一次处理任务摘要，前端重新进入详情后基于该任务继续查询进度和结果。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登录后进入个人工作空间 (Priority: P1)

已登录用户进入系统时，默认看到属于自己的工作空间，并能在该空间内查看已经创建的应用。

**Why this priority**: 工作空间是后续创建、查看和进入应用的入口；没有明确的默认入口，用户无法稳定开始工作。

**Independent Test**: 使用一个已登录账号进入系统，确认首屏显示该账号自己的工作空间，并且不会展示其他账号的应用。

**Acceptance Scenarios**:

1. **Given** 用户已登录且拥有默认工作空间，**When** 用户打开系统，**Then** 系统默认展示该用户自己的工作空间。
2. **Given** 用户已登录但还没有任何应用，**When** 用户进入自己的工作空间，**Then** 系统展示空应用列表状态，并提供创建应用的入口。
3. **Given** 用户 A 和用户 B 都拥有应用，**When** 用户 A 进入自己的工作空间，**Then** 用户 A 只能看到自己工作空间中的应用。
4. **Given** 用户首次登录且尚无工作空间，**When** 用户打开系统，**Then** 系统自动创建个人默认工作空间并进入该工作空间。

---

### User Story 2 - 在工作空间中创建和浏览多个应用 (Priority: P2)

用户可以在自己的工作空间中创建多个应用，通过卡片列表快速识别、浏览和进入目标应用，并能维护应用基础信息。

**Why this priority**: 多应用管理是工作空间的核心价值，卡片视图让用户能以可扫描的方式管理应用集合。

**Independent Test**: 在一个用户的工作空间中连续创建多个应用，确认每个应用都以独立卡片展示，并且可以编辑应用基础信息后在卡片和详情中看到更新。

**Acceptance Scenarios**:

1. **Given** 用户位于自己的工作空间，**When** 用户创建一个新应用并填写必填信息，**Then** 新应用出现在工作空间的应用卡片列表中。
2. **Given** 用户已创建多个应用，**When** 用户查看工作空间，**Then** 每个应用以一张卡片展示，并包含应用名称、简要描述或状态、最近更新时间。
3. **Given** 用户提交的应用名称为空、不符合规则或与同一工作空间内已有应用重名，**When** 用户尝试创建应用，**Then** 系统阻止创建并提示可理解的修正信息。
4. **Given** 用户已创建应用，**When** 用户编辑该应用名称或应用说明并保存，**Then** 应用卡片和详情页展示更新后的信息。
5. **Given** 用户位于工作空间首版界面，**When** 用户查看应用操作，**Then** 系统不提供删除应用入口。

---

### User Story 3 - 进入应用并进行流程编排 (Priority: P3)

用户从应用卡片进入某个应用后，看到左侧应用相关信息和右侧应用编排画布入口，首版用于确认后续流程编排区域，不支持编辑流程。

**Why this priority**: 应用进入后的核心工作入口是流程编排，首版必须让应用上下文和编排画布入口同时可见。

**Independent Test**: 从任一应用卡片进入应用详情，确认页面左侧稳定展示应用信息，右侧展示空画布和开始编排入口，且不提供流程编辑能力。

**Acceptance Scenarios**:

1. **Given** 用户在工作空间中看到一个应用卡片，**When** 用户打开该应用，**Then** 系统展示应用详情页面，左侧为应用相关信息，右侧为编排画布。
2. **Given** 用户位于应用详情页面，**When** 用户查看左侧信息区，**Then** 用户能识别当前应用名称、说明和基础状态。
3. **Given** 用户位于应用详情页面，**When** 用户查看右侧区域，**Then** 用户能看到用于基于流程进行编排的空画布和入口。
4. **Given** 用户位于首版应用详情页面，**When** 用户尝试寻找流程编辑操作，**Then** 系统不展示新增、移动、连接或删除节点的编辑能力。

---

### Edge Cases

- 用户首次登录但默认工作空间尚未初始化时，系统应自动创建个人默认工作空间并进入；如果创建失败，应明确提示初始化失败原因。
- 用户工作空间没有应用时，应显示空状态和创建入口，而不是空白页面。
- 用户在同一工作空间内创建同名应用时，系统应阻止创建并提示应用名称已存在；不同工作空间之间的应用名称可重复。
- 用户编辑应用名称后导致名称与同一工作空间内已有应用重名时，系统应阻止保存并提示应用名称已存在。
- 用户尝试进入不存在、已删除或不属于自己的应用时，系统应拒绝访问并给出明确提示。
- 应用数量较多时，卡片列表应保持可浏览，不应阻塞用户进入已有应用。
- 编排画布在首版始终显示空画布状态和开始编排入口，不提供节点编辑操作。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在用户登录成功后默认进入该用户自己的工作空间。
- **FR-002**: 系统 MUST 确保用户只能查看和操作自己有权限访问的工作空间内容。
- **FR-003**: 系统 MUST 支持每个用户至少拥有一个默认工作空间，并在用户首次登录且无工作空间时自动创建个人默认工作空间。
- **FR-004**: 用户 MUST 能在自己的工作空间中创建应用。
- **FR-005**: 创建应用时，系统 MUST 至少要求用户提供应用名称，并对无效名称给出明确提示。
- **FR-006**: 系统 MUST 支持一个工作空间包含多个应用，并确保同一工作空间内应用名称唯一。
- **FR-007**: 系统 MUST 在工作空间中以卡片方式展示应用列表。
- **FR-008**: 应用卡片 MUST 至少展示应用名称、简要说明或状态、最近更新时间，以及进入应用的交互入口。
- **FR-009**: 用户 MUST 能从应用卡片进入对应应用详情。
- **FR-010**: 用户 MUST 能编辑应用名称和应用说明并保存更新。
- **FR-011**: 首版系统 MUST NOT 提供删除应用能力。
- **FR-012**: 应用详情页面 MUST 同时展示应用相关信息区和应用编排画布区。
- **FR-013**: 应用详情页面的左侧区域 MUST 展示当前应用的基础信息，使用户能确认正在编辑的应用。
- **FR-014**: 应用详情页面的右侧区域 MUST 展示用于基于流程进行编排的空画布和入口。
- **FR-015**: 首版系统 MUST NOT 提供新增、移动、连接、删除节点等流程编辑能力。
- **FR-016**: 系统 MUST 对不存在、已删除或无权访问的工作空间和应用返回明确错误语义，避免用户误以为数据丢失。
- **FR-017**: 该功能的规格与后续实现分支 MUST 使用独立 git worktree 创建和绑定，保证开发活动发生在对应 worktree 中。
- **FR-018**: 知识库文件解析、切分、向量化和索引任务 MUST 使用后端持久化任务状态管理，前端页面切换、刷新或关闭后重新进入知识库详情时 MUST 能恢复最近任务状态、进度和可查询的处理结果。

### Key Entities

- **用户**: 已认证的系统使用者，拥有自己的默认工作空间，可在权限范围内访问工作空间和应用。
- **工作空间**: 用户进入系统后的默认工作区域，承载该用户创建和管理的应用集合；用户首次登录且无工作空间时自动创建个人默认工作空间。
- **应用**: 工作空间中的业务编排对象，包含名称、说明、状态、更新时间和流程编排内容；名称在所属工作空间内必须唯一；首版支持编辑名称和说明但不支持删除。
- **应用卡片**: 工作空间中用于展示单个应用摘要和进入入口的可视化条目。
- **编排画布**: 应用详情中的流程编排区域；首版仅展示空画布和入口，不承载可编辑流程内容。

## Success Criteria *(mandatory)*

- **SC-001**: 95% 的已登录用户能在 2 秒内看到自己的工作空间首屏内容。
- **SC-002**: 用户能在 1 分钟内从空工作空间完成第一个应用创建并看到对应应用卡片。
- **SC-003**: 用户能在 2 次点击以内从工作空间进入任一已有应用的详情页面。
- **SC-004**: 90% 的测试用户能在无说明文档辅助下识别应用信息区、空画布区和开始编排入口。
- **SC-005**: 对无权访问应用的尝试，100% 都不会展示受保护应用内容，并给出明确反馈。
- **SC-006**: 用户能在 1 分钟内完成一次应用名称或说明编辑，并在工作空间卡片和应用详情中看到一致结果。
- **SC-007**: 用户上传 PDF 触发知识库解析后，即使切换到其他页面或关闭页面，再次进入该知识库详情时也能看到同一处理任务的当前状态和进度。

## Assumptions

- 目标用户已经完成登录，本规格不重新定义注册、登录、会话管理能力。
- 每个用户默认拥有一个个人工作空间；若用户首次登录时尚不存在该空间，系统自动创建；多成员协作、组织级空间、共享权限不包含在本功能范围内。
- 应用创建的最小信息为名称，说明、状态和更新时间可作为应用摘要信息展示。
- 首版应用管理包含创建、查看卡片、进入详情和编辑应用名称与说明；删除应用不包含在本规格范围内。
- 编排画布本阶段只展示空画布和开始编排入口；流程编辑、节点配置、执行调试和发布能力不包含在本规格范围内。
- 该 feature 的分支与工作目录使用 git worktree 绑定，后续计划、任务和实现均应在对应 worktree 中进行。
